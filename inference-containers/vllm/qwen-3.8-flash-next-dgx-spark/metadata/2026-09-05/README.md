## 🛠️ How These Files Were Generated

### 1. Generating the Log Dump (`01_vllm_log.txt`)
The raw logs were extracted directly from the running vLLM inference container using the preset's log dump script:

```bash
cd inference-containers/vllm/qwen-3.8-flash-next-dgx-spark/mia-nvfp4
./05_b_dump_logs.sh
```

**Security & Sanitization:**
- Sourced from [`05_b_dump_logs.sh`](../../05_b_dump_logs.sh), which invokes `docker_logs_dump_container` from `commonScripts/lib.sh`.
- Automatically sanitizes `'api_key': ['...']` and replaces the `$INFERENCE_API_KEY` credential with `dummy-key`.
- Includes an assertion check that halts and purges the file if any sensitive strings are detected, guaranteeing zero leaked passwords.

### 2. Generating the Performance Report (`01_vllm_log.report.md`)
The markdown report was generated using the dedicated vLLM log parser:

```bash
bash inference-containers/vllm/log-parser/03_parse_docker_log_file_to_markdown_report.sh \
  inference-containers/vllm/qwen-3.8-flash-next-dgx-spark/mia-nvfp4/metadata/2026-09-05/01_vllm_log.txt
```

**Parser Processing & Features:**
- Executed in the `testVLLMLogParse` conda environment via `parse_docker_log.py`.
- Normalized container timestamps across Style A and Style B logging.
- Paired 10-second `Engine 000:` throughput samples with companion `SpecDecoding metrics:` lines.
- Extracted startup parameters, memory footprints, KV cache token limits, and PLE offload stats.
- Classified 100% of lines (`unrecognized=0` canary status) with 532 boilerplate lines categorized into Section 6 noise families.
